# Conversation Review

> **和AI聊了一整天，活干了不少，想复盘，但无从下手？那就用这个SKILL！**

## 使用最佳姿势

### 1. 对话分类，窗口独立

零散问题（查概念、问语法、临时 debug）和系统性任务对话（功能开发、架构设计、问题排查）应使用**各自独立的对话窗口**。
- 窗口独立能保持上下文纯净，提升大模型在对话中的理解和总结质量
- 最终生成的报告文件独立，便于快速对所有零散问题回顾和系统性任务回顾，避免一个文件夹在着对零散问题和系统性任务的回顾。

### 2. 复盘即终点，不再追加

触发 `/conversation-review` 后，当前窗口应视为**已结束**，不再追加新问题。

- 该 Skill 会**全量总结**当前对话的全部内容
- 若总结后再追加问题并二次总结，前部分内容会被重复处理，浪费 token
- 这也违背了复盘的本质——复盘是对"已完成"的回顾，既已完成，不应再有后续

### 3. 触发时机

该 Skill 的设计意图是**阶段性收尾**，适合在以下时机使用：

- ✅ 一天工作结束时
- ✅ 某个任务/功能完成时
- ✅ 一次完整的问题排查结束时
- ❌ 对话中途（尚未形成完整上下文）
- ❌ 刚开始一个问题时

## 快速使用

### 1. 安装 Skill

#### Cursor

```bash
# macOS / Linux
cp -r conversation-review ~/.cursor/skills/conversation-review

# Windows (PowerShell)
Copy-Item -Recurse -Force conversation-review "$env:USERPROFILE\.cursor\skills\conversation-review"
```

#### Claude Code

```bash
# macOS / Linux
cp -r conversation-review ~/.claude/skills/conversation-review

# Windows (PowerShell)
Copy-Item -Recurse -Force conversation-review "$env:USERPROFILE\.claude\skills\conversation-review"
```

#### Codex

```bash
# macOS / Linux
cp -r conversation-review ~/.codex/skills/conversation-review

# Windows (PowerShell)
Copy-Item -Recurse -Force conversation-review "$env:USERPROFILE\.codex\skills\conversation-review"
```

### 2. 在对话中触发

- `/conversation-review`
- 「帮我做对话回顾」
- 「分析一下这次对话」

### 3. 查看报告

报告生成在当前工作目录下：

```
conversation-reviews/
└── review-YYYYMMDD-HHmmss.md
```

## 核心功能

| 功能 | 说明 |
|------|------|
| **自动捕获** | 从对话中提取用户问题，无需手动记录 |
| **意图分析** | 结合问答内容，理解用户真正想了解什么 |
| **合并追问** | 同一主题的连续追问合并为一条，避免碎片化 |
| **关键点记录** | 从 AI 回答中提炼核心要点，回顾时不遗忘 |
| **原话保留** | 用户原话以「原问题」引用形式保留，还原上下文 |
| **代码引用** | 记录文件路径和行号，回顾时快速定位 |

```markdown
## 问题列表

1. **多Agent协作中，如何防御低权限Agent诱骗高权限Agent执行越权操作**

   > 原问题：怎么解决多Agent协作时，低权限Agent诱骗高权限Agent

   关键点：
   - 本质是**间接提示注入（Indirect Prompt Injection）**攻击，常见模式：数据投毒、身份伪装、逐步诱导
   - **输入净化**：高权限Agent接收子Agent输出时，必须用 `[UNTRUSTED_DATA]` 标记并清洗指令性内容
   - **权限最小化**：每个Agent只暴露完成任务所需的最小工具/路径/操作权限
   - **信任边界隔离**：子Agent输出永远视为不可信数据，由高权限Agent自行判断，而非直接当作指令执行
   - **输出验证**：执行前验证操作是否在任务范围内、是否符合最小权限、是否异常
   - **人类在环**：关键操作（如 execute、delete）必须有人类审批
   - 核心原则：零信任、最小权限、职责分离、可观测性

2. **提示词过于具体导致模型机械化执行，环境变化时出错，如何调整**

   > 原问题：在很多场景中，提示词写的过于具体反而会让模型机械化中执行，一旦环境发生变化，就会错误，这种情况应当如何调整提示词

   关键点：
   - 核心矛盾：**精确性 vs 适应性**——过度具体让模型当 if-else 执行，过度模糊让输出不可控
   - **从"规则"转向"原则"**：告诉模型"为什么这样做"而非"做什么"，让模型理解目标而非死板执行步骤
   - **用"边界"代替"路径"**：规定能力范围（可以/不可以），而非规定具体执行步骤，留出判断空间
   - **用"示例"代替"描述"**：示例天然包含隐含的决策逻辑，比文字描述更难被机械化执行
   - **分层提示设计**：角色与目标（稳定）→ 原则与边界（较稳定）→ 具体策略（可变）→ 示例（动态）
   - 过拟合信号：遇到新情况直接报错、环境微小变化导致完全错误、不断需要补充规则
   - 一句话总结：好的提示词是告诉模型"目标是X，边界是Y，不确定时优先Z"

```
