## 问题列表

1. **SQLAlchemy 中 flush 和 commit 的区别，以及事务何时提交**
   > 原问题：「这里为什么要flush」「那这里的插入什么时候执行commit」

   关键点：
   - `flush`：将 SQL 发送到数据库执行，但**不提交事务**，可获取自增 ID、触发约束校验
   - `commit`：先 flush 再提交事务，数据对其他事务可见
   - 事务由 `create_session` 依赖统一管理：路由正常结束自动 `commit`，异常自动 `rollback`
   - 路由函数内只需 `flush`，不需要自己 `commit`

2. **FastAPI yield 依赖注入的实现原理**
   > 原问题：「这个原理是怎么实现的，为什么是先返回数据，然后再yield处恢复」

   关键点：
   - `yield` 让函数变成生成器，执行到 `yield` 暂停并保存现场
   - FastAPI 通过 `next(gen)` 获取 yield 的值（session），交给路由函数使用
   - 路由函数结束后，再次 `next(gen)` 恢复执行 yield 之后的代码（commit/close）
   - `yield` 前 = 请求开始时执行，`yield` 后 = 请求结束时执行

3. **session.delete() 为什么要求对象必须是持久化状态，以及 ORM 与 SQL 思维的区别**
   > 原问题：「Instance '<Book>' is not persisted 为什么」「为什么delete要先查询出book」「ORM思维」

   关键点：
   - `session.delete(obj)` 要求 obj 是从数据库查出来的（persistent 状态），不能是 `Book(id=1)` 新建对象
   - 原因：Session 有**身份映射（Identity Map）**，只认识它跟踪过的对象
   - 支持**级联删除**：需要加载关联对象才能根据 cascade 策略处理
   - ORM 思维 = 操作对象关系图，SQL 思维 = 操作单条记录
   - 不想先查再删，可用 `delete(Book).where(Book.id == 1)` 直接执行 SQL

4. **ORM 更新接口实现及 PyCharm 类型警告**
   > 原问题：「这个(update)应该怎么实现」「为什么这里再pycharm中黄色警告」「这样还是报警」

   关键点：
   - 更新接口：先查询出对象，修改属性，由 `create_session` 自动 commit
   - PyCharm 警告原因：FastAPI 请求体参数要求 `BaseModel`（Pydantic），不能直接用 ORM 模型（`Base`）
   - 解决：使用 `BookDTO` 或 `BookUpdate`（继承 `BaseModel`）作为请求体参数

5. **ORM 脏标记追踪（Dirty Tracking）机制**
   > 原问题：「这个修改的底层逻辑是什么」

   关键点：
   - ORM 字段是描述符（descriptor），setter 中有事件钩子
   - 属性被修改时自动通知 Session 标记为 dirty
   - commit 时 Session 检查所有 dirty 对象，只 UPDATE 被修改的字段
   - 与查询方式无关，只关注对象属性是否被修改

6. **Java 与 Python 包命名及导入机制的区别**
   > 原问题：「为什么java的包名建议是com.公司名」「java里没法给包起别名是吗」「你说java是全局引入是什么意思」「Python的导入不会包全局包名冲突」

   关键点：
   - Java 包名用反向域名（`com.xxx`）解决全局命名冲突，没有别名机制
   - Python 用 PyPI 注册解决包名冲突，有 `as` 别名机制
   - Java 的 `import` 是编译期名称简写（语法糖），Python 的 `import` 是运行时加载模块
   - Python 不会全局包名冲突，但会模块名冲突（如本地文件与标准库同名），可用别名解决

7. **lifespan 生命周期函数与 @asynccontextmanager**
   > 原问题：「lifespan是干嘛的，@asynccontextmanager又是干嘛的」「为什么服务启动时，这里的lifespan没有启动」「一个服务只能有一个lifespan函数是吗」「AsyncExitChain是干嘛的」「lifespan的参数是fastapi实例是吗」

   关键点：
   - `lifespan`：FastAPI 的启动/关闭钩子，`yield` 前 = 启动逻辑，`yield` 后 = 关闭逻辑
   - `@asynccontextmanager`：将普通 async 函数变成上下文管理器，省去写 `__aenter__`/`__aexit__`
   - 一个应用只能注册一个 lifespan，组合多个用 `AsyncExitStack`（按顺序启动，逆序关闭）
   - `app` 参数是 FastAPI 实例，大多数时候不需要使用
   - lifespan 未生效：检查是否正确导入并注册到 `FastAPI(lifespan=...)`

8. **Python 模块导入路径问题（sys.path）**
   > 原问题：「ModuleNotFoundError: No module named 'basic_study'」「为什么basic_study不在sys.path里」「No module named 'orm'」

   关键点：
   - `sys.path` 只包含当前工作目录和脚本所在目录，不包含父目录
   - 在 `basic_study` 目录下运行 → 找不到 `basic_study` 包（父目录不在 sys.path）
   - 在 `fastapi-study` 目录下运行 → 找不到 `orm` 模块（需要加 `basic_study.` 前缀）
   - 解决：在父目录运行 + 所有导入加包名前缀，或用相对导入（`from .orm import ...`）

9. **Depends 依赖函数是否必须是 async**
   > 原问题：「Depends的函数必须是async的吗」

   关键点：
   - 不是必须的，普通函数和 async 函数都可以
   - 取决于函数内部是否有异步操作（`await`）
   - FastAPI 自动识别并正确处理两种情况
