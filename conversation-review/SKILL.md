# Conversation Review

**自动捕获问题，分析意图，合并相似，记录关键点**。用户在对话中专心提问，skill 自动整理问题和解答要点。

## 输出语言

面向用户的输出**与用户在本对话中使用的主要语言保持一致**。

## 工作流程

```
回顾进度：
- [ ] 1. 捕获并分析用户问题
- [ ] 2. 合并相似问题
- [ ] 3. 记录解答关键点
- [ ] 4. 生成 Markdown 报告
```

### 步骤 1 — 捕获并分析用户问题

从当前对话中提取**用户提出的问题**，结合 AI 的回答分析问题的真实意图：

| 原则 | 说明 |
|------|------|
| 分析意图 | 结合问答内容，理解用户真正想了解什么 |
| 保留原话 | 引用用户原始表述，标注为「原问题」 |
| 适当补充 | 基于意图分析，补充关键词使问题更清晰 |
| 跳过应答 | 跳过纯应答（`好的`、`继续`、`ok`、`thanks`） |

**展示规则：**

| 情况 | 展示方式 |
|------|---------|
| 原话已清晰 | 直接展示，无「原问题」引用 |
| 原话需要补充 | 展示补充后内容，原话以「原问题」引用出现 |
| 跳过应答 | 不记录 |
| 相似问题 | 合并为一条，原问题引用包含所有相关问题 |

### 步骤 2 — 合并相似问题

同一主题的连续追问或相关问题应合并为一条，避免碎片化：
- 同一主题的追问合并（如 "左连接区别？" + "那右连接呢？" → 一条）
- 问题指向同一概念的不同方面合并
- 不同表述问同一问题合并

### 步骤 3 — 记录解答关键点

从 AI 的回答中提取**关键知识点**，记录在问题下方：
- 提炼核心要点，不要复制全部回答
- 保留关键概念、原理、用法、注意事项
- 使用简洁的要点格式

### 步骤 4 — 生成 Markdown 报告

报告格式详见 [references/structure.md](references/structure.md)。

在当前工作目录下生成 `conversation-reviews/review-YYYYMMDD-HHmmss.md`。

在聊天中给出 MD 文件的完整绝对路径，提示用户查看。

## 输出顺序

1. Markdown 摘要（聊天内，列出捕获的问题和关键点）
2. 报告文件路径
