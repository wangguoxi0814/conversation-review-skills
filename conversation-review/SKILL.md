# Conversation Review

**自动捕获问题，分析意图，合并相似，记录关键点**。用户在对话中专心提问，skill 自动整理问题和解答要点。

## 输出语言

面向用户的输出**与用户在本对话中使用的主要语言保持一致**。

## 工作流程

```
回顾进度：
- [ ] 1. 捕获并分析用户问题
- [ ] 2. 合并相似问题
- [ ] 3. 记录解答关键点
- [ ] 4. 生成 Markdown 报告
```

### 步骤 1 — 捕获并分析用户问题

从当前对话中提取**用户提出的问题**，结合 AI 的回答分析问题的真实意图：

| 原则 | 说明 |
|------|------|
| 分析意图 | 结合问答内容，理解用户真正想了解什么 |
| 保留原话 | 引用用户原始表述，标注为「原问题」 |
| 适当补充 | 基于意图分析，补充关键词使问题更清晰 |
| 跳过应答 | 跳过纯应答（`好的`、`继续`、`ok`、`thanks`） |

**意图分析示例：**

| 对话 | 用户原话 | 分析意图 | 整理后问题 |
|------|---------|---------|-----------|
| 用户: volatile 为啥不行<br>AI: [解释可见性但不保证原子性...] | volatile 为啥不行 | 用户在问 volatile 的局限性 | volatile 为什么不能保证原子性？ |
| 用户: 那个注解怎么用<br>AI: @Transactional 可以... | 那个注解怎么用 | 用户在问 @Transactional 的用法 | @Transactional 注解怎么用？ |
| 用户: 报错了 NPE<br>AI: 因为 user 对象为 null... | 报错了 NPE | 用户在问 NPE 的原因和修复 | NPE 空指针异常的定位与修复方法 |

### 步骤 2 — 合并相似问题

同一主题的连续追问或相关问题应合并为一条，避免碎片化：

**合并规则：**
- 同一主题的追问合并（如 "左连接区别？" + "那右连接呢？" → 一条）
- 问题指向同一概念的不同方面合并
- 不同表述问同一问题合并

**合并示例：**

| 原始问题 | 合并后 |
|---------|-------|
| "左连接、右连接的区别？"<br>"那全外连接呢？"<br>"INNER JOIN 呢？" | 左连接、右连接、全外连接、内连接的区别是什么？ |
| "volatile 怎么用？"<br>"为什么不能保证原子性？" | volatile 的用法及为什么不能保证原子性 |
| "Spring AI 的 Tool Calling 怎么用？"<br>"和 Function Calling 什么关系？" | Spring AI Tool Calling 的用法及其与 Function Calling 的关系 |

### 步骤 3 — 记录解答关键点

从 AI 的回答中提取**关键知识点**，记录在问题下方，帮助用户回顾时快速回忆：

**关键点要求：**
- 提炼核心要点，不要复制全部回答
- 保留关键概念、原理、用法、注意事项
- 使用简洁的要点格式

**示例：**

```markdown
1. **volatile 为什么不能保证原子性？**
   > volatile 为啥不行

   关键点：
   - volatile 保证可见性：修改后立即刷新到主存
   - 不保证原子性：i++ 实际是读-改-写三步操作
   - 解决方案：使用 AtomicInteger 或 synchronized
```

### 步骤 4 — 生成 Markdown 报告

在当前工作目录下生成 `conversation-reviews/review-YYYYMMDD-HHmmss.md`：

```bash
mkdir -p conversation-reviews
```

报告格式：

```markdown
# 对话回顾 · YYYY-MM-DD HH:MM

## 问题列表

1. **volatile 为什么不能保证原子性？**
   > 原问题：volatile 为啥不行

   关键点：
   - volatile 保证可见性：修改后立即刷新到主存
   - 不保证原子性：i++ 实际是读-改-写三步操作
   - 解决方案：使用 AtomicInteger 或 synchronized

2. **左连接、右连接、全外连接、内连接的区别是什么？**
   > 原问题：左连接、右连接的区别是什么？那全外连接呢？

   关键点：
   - LEFT JOIN：返回左表所有行，右表无匹配则为 NULL
   - RIGHT JOIN：返回右表所有行，左表无匹配则为 NULL
   - FULL JOIN：返回两表所有行，无匹配则为 NULL
   - INNER JOIN：只返回两表都匹配的行

3. **Spring Boot 自动配置原理**
   *(原问题已清晰，无额外引用)*

   关键点：
   - @SpringBootApplication 包含 @EnableAutoConfiguration
   - 读取 META-INF/spring.factories 中的配置类
   - 通过 @Conditional 注解按条件加载

---
*Generated by conversation-review skill*
*Source: [conversation-review-skills](git@github.com:wangguoxi0814/conversation-review-skills.git)*
```

在聊天中给出 MD 文件的完整绝对路径，提示用户查看。

## 输出顺序

1. Markdown 摘要（聊天内，列出捕获的问题和关键点）
2. 报告文件路径
