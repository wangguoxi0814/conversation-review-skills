# Conversation Review — 目录结构

## 总览

```
conversation-review/
├── SKILL.md                          # 主入口：工作流与触发说明
└── references/
    └── structure.md                  # 本文件：架构说明

当前工作目录（运行时生成）：
└── conversation-reviews/
    └── review-YYYYMMDD-HHmmss.md     # 对话回顾报告
```

## 设计原则

| 原则 | 说明 |
|------|------|
| 范围 | 仅当前对话框；不读 agent-transcripts |
| 自动捕获 | 从对话中提取用户问题 |
| 意图分析 | 结合问答内容分析用户真实意图 |
| 合并相似 | 同一主题问题合并，避免碎片化 |
| 记录关键点 | 提炼解答中的核心知识点 |
| 保留原话 | 引用用户原始表述，标注「原问题」 |
| 适当补充 | 补充关键词使问题更清晰 |
| 用户专注 | 用户专心对话，无需手动记录 |
| 简洁输出 | Markdown 格式，无额外依赖 |
| 语言 | 输出与用户对话语言一致 |

## 问题捕获规则

### 意图分析

结合用户问题和 AI 回答，分析用户真正想了解的内容：

| 对话 | 用户原话 | 分析意图 | 整理后问题 |
|------|---------|---------|-----------|
| 用户: volatile 为啥不行<br>AI: [解释可见性...] | volatile 为啥不行 | 问 volatile 的局限性 | volatile 为什么不能保证原子性？ |
| 用户: 那个注解怎么用<br>AI: @Transactional... | 那个注解怎么用 | 问 @Transactional 用法 | @Transactional 注解怎么用？ |

### 合并规则

| 原始问题 | 合并后 |
|---------|-------|
| "左连接区别？" + "那右连接呢？" + "全外连接呢？" | 左连接、右连接、全外连接的区别 |
| "volatile 怎么用？" + "为什么不能保证原子性？" | volatile 的用法及为什么不能保证原子性 |

### 关键点提取

从 AI 回答中提炼核心要点：
- 关键概念和原理
- 具体用法和示例
- 注意事项和常见陷阱
- 解决方案和最佳实践

## 报告格式

### 文件命名

`conversation-reviews/review-YYYYMMDD-HHmmss.md`

### 内容结构

```markdown
# 对话回顾 · YYYY-MM-DD HH:MM

## 问题列表

1. **补充关键词后的清晰表述**
   > 原问题：用户原话

   关键点：
   - 要点1
   - 要点2

2. **原话已清晰的问题**
   *(无原问题引用)*

   关键点：
   - 要点1
   - 要点2

---
*Generated by conversation-review skill*
*Source: [conversation-review-skills](git@github.com:wangguoxi0814/conversation-review-skills.git)*
```

### 展示规则

| 情况 | 展示方式 |
|------|---------|
| 原话已清晰 | 直接展示，无「原问题」引用 |
| 原话需要补充 | 展示补充后内容，原话以「原问题」引用出现 |
| 跳过应答 | 不记录 |
| 相似问题 | 合并为一条，原问题引用包含所有相关问题 |
